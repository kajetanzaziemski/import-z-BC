# Project notes

- This is a **Google Apps Script add-on for Google Sheets** (managed with clasp; `.clasp.json`), currently published in the Google Workspace Marketplace SDK **privately** (testers only, within the domain). Treat changes as affecting a live add-on.
- `CLIENT_ID_`, `CLIENT_SECRET_` and `SCOPE_` are JS consts defined in an untracked file (`Autoryzacja-credentials.js`, in `.gitignore`) whose name starts with `00` so it sorts first in the clasp file list. Treat them as defined.
- Storage: all stored data goes through `Store` (`Store.js`; `HelperDataStore` is only its implementation), the add-on's settings through `Settings` (`Settings.js`; `MainSettings` forwards to it). `getImportSettings()` is a `StorageObject` over document properties (`Settings.store()`). Executions run concurrently (onEdit, onChange, time triggers), so `StorageObject.saveArray()` writes only the keys changed via `setProperty()`, merged under a lock. Never write a whole snapshot back.
- Time-based triggers are managed through a "refresh permit" (`MainSettings.*RefreshPermit`): a trigger runs only if `permit.issuedFor === e.triggerUid`, otherwise it deletes itself. Time-based triggers are not returned by `ScriptApp.getUserTriggers(ss)`; use `getProjectTriggers()`.
- Tests: `node tests/run.js` runs `Grid.js` and `Config Grid.js` against a simulated spreadsheet, and the state layer (Store, Settings, locks, agent-detection state) against fake Properties/Cache/Lock services (`tests/sim.js`) through both commit paths, with golden tests against the frozen pre-Grid code (`tests/golden/`); see `docs/testing.md` (incl. the manual real-spreadsheet check). `.claspignore` keeps `tests/` and `docs/` out of the push (the tests use Node-only `require`). Nothing is verified against a real spreadsheet.
- Build version: `Version.js` (written by `tools/stamp-version.sh`) is shown in the developer tools sidebars. Run the script before every commit (it records the commit the new one is built on, with a `+`) and before `clasp push` (exact commit when the tree is clean); self-reported, see `docs/live-check.md`.
- Agents (the installable trigger pairs): everything outside `Trigger Manager.js` / `Status Manager.js` / `Track onEdit Triggers.js` / `Agents.js` goes through the facade `Agents`; `docs/agent-lifecycle.md` says when they are created, replaced and destroyed (read it before changing anything there; the quirks in it are pinned by `tests/agents.test.js`).
- Live check helpers (`Live Check*.js`, from branch `live-test-helpers`, see `docs/live-check.md`) verify entry points against the add-on as it was before the refactor. Do not edit them to fit refactored code (they are pinned in `tests/golden/live-check.sha256.json`); they read stored data directly on purpose, not through `Store` / `Settings`.
- Edits and structure changes reach the use cases through the router (`Router.js`, `docs/router.md`): a technical trigger (`sheetEdit`, `sheetChange`) is turned into a named job (`config.coedit`, `settings.refreshFrequency`, `sheet.ignored` ...) announced with `Controller.intent`; the live check reports and judges runs by job. A new job needs a route, a `LIVE_CHECK_INTENTS` entry and a verifier of the same name.
- Every platform entry (trigger, menu item, sidebar call, OAuth callback) is wrapped by `Controller.run`, one run per execution, no nested runs (`docs/controller.md`); the only exception is building the menu at the start of `onOpen`. Settings and trigger logs are saved by closing actions, so a change made outside a run is not saved. Shared work lives in use cases, never in a second entry point.
